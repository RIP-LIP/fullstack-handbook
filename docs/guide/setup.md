# 第0章 先把环境配好

> 目标：装好 Node.js、确认终端能用、跑通一次 `npm install`。全程 20 分钟。**不要跳过这一章。**

后面每一章都要开两个终端、看着两个进程日志。环境没配好，你在第 1 章看到的第一个报错大概率是「命令不是内部或外部命令」，而不是你想学的东西。

## 1. 你需要装的三样东西

| 要装 | 是什么 | 装完怎么确认 |
| --- | --- | --- |
| Node.js | 运行 JavaScript 的程序 | `node -v` 有输出 |
| npm | 装依赖的工具，Node 自带 | `npm -v` 有输出 |
| 编辑器 | 写代码用 | 能打开 `.ts` 文件 |

**数据库不用装。** 后面会用 SQLite，它是个文件，不需要装服务、不需要配账号密码。

## 2. 装 Node.js

打开 <https://nodejs.org>，下载 **LTS** 版本（LTS = 长期支持版，比 Current 稳）。

::: warning 别装 Current 版
页面上有两个大按钮：**LTS** 和 **Current**。选 LTS。
Current 是追新功能的，出问题概率高，你的教程不需要那些新特性。
:::

装完**关掉终端重新开一个**，然后：

```bash
node -v
npm -v
```

| 你看到 | 说明 |
| --- | --- |
| `v22.x.x` 或更高 | 够了，继续 |
| `v18.x.x` | 偏老，先去官网装新版 |
| `'node' 不是内部或外部命令` | 见下一节 |

## 3. 改了环境变量要重开终端

装完 Node 后，**必须关掉当前终端窗口，重新开一个**。不是开新标签页，是把整个窗口关掉重开。

原因：终端启动的那一刻会把系统的 PATH 读一遍，之后就不再重新读了。装 Node 改的就是 PATH，但在装之前就已经打开的终端，手里那份还是旧的。

**判断方法**：

```bash
echo %PATH%
```

（macOS / Linux 用 `echo $PATH`）

里面能找到 Node 的安装路径就对了。

::: details 装完还是提示「不是内部或外部命令」
按顺序试：

1. 关掉终端整个窗口重开（不是新标签页）
2. 装的时候勾了「Add to PATH」吗？没勾就重新运行安装包
3. 装完重启电脑

三步都还不行，先确认你装的是不是真的 Node.js，而不是一个叫「Node」的其他软件。
:::

## 4. 认识一下终端

后面全篇都在终端里操作，花两分钟知道这几个概念。

**你输入的一行命令，由三部分组成：**

```bash
npm run dev:api
│  │   └── ③ 参数：给命令的额外信息
│  └────── ② 子命令：这个命令要做什么
└───────── ① 命令名：要运行哪个程序
```

**你在哪个目录**，决定了命令作用在哪些文件上。看当前目录：

```bash
# Windows
dir

# macOS / Linux
ls
```

看到 `package.json` 就说明位置对了。

::: danger 最常见的新手错误
在错误的目录里执行 `npm install`，结果是什么都没装上还以为是网络问题。
**每条命令执行前，先 `dir` 确认一下。**
:::

**怎么停止一个卡住的命令**：在终端里按 `Ctrl + C`。不是关窗口——关窗口会留下孤儿进程占着端口。

## 5. 装编辑器

VS Code 或任何你顺手的编辑器。这不是必须的——你也可以用记事本——但有语法高亮和报错提示会省很多事。

装完顺手做一件事：**确认你的编辑器终端和上面这个是同一个终端**。很多编辑器自带终端，长得和系统终端一样，但不是同一个，它们的当前目录是分开的。

## 6. 拿到项目

```bash
git clone https://github.com/RIP-LIP/fullstack-todo-app.git
cd fullstack-todo-app
dir
```

应该看到：

```text
apps  node_modules  package.json  ...
```

::: tip `git` 没有怎么办
Windows 装 <https://git-scm.com>，装完重开终端。其他系统自带。
:::

## 7. 装依赖

在**刚才能看到 `package.json` 的那个目录**里：

```bash
npm install
```

这一步会下载几百个包，第一次慢是正常的。等它跑完。

::: warning `node_modules` 不是一个文件夹，是几万个文件
装完项目里会多出一个巨大的 `node_modules` 目录。**不要手动去翻它**，也不要把它提交到 git（`.gitignore` 已经帮你挡住了）。
:::

## 8. 验证环境真的好了

装完依赖后，**先只跑一个服务**：

```bash
npm run dev:api
```

看到这样的输出就成了：

```text
[api] 已启动 → http://localhost:3001
```

**别急着关掉。** 再开一个新终端验证一下：

```bash
curl -i http://localhost:3001/api/health
```

看到 `HTTP/1.1 200 OK` 和 `{"ok":true,"service":"api"}`，说明 Node、依赖、网络、后端服务全都通了。

到这一步，环境部分结束。

## 常见问题

| 现象 | 先做这个 |
| --- | --- |
| `node` 不是内部或外部命令 | 关掉终端整个窗口重开 |
| `npm install` 卡住不动 | 换国内镜像，见 [下一节](#_9-装依赖太慢) |
| `npm install` 报权限错误 | 别加 `sudo`，先看 [下一节](#_9-装依赖太慢) |
| 端口 3001 被占用 | 记下来，第 1 章会处理 |

## 9. 装依赖太慢

`npm install` 默认去官方源下载，国内可能很慢或超时。换成镜像源：

```bash
npm config set registry https://registry.npmmirror.com
```

配完再跑一次 `npm install`。

::: tip 这个配置是全局的，只影响你之后所有项目的下载源
如果不想永久改，可以只在当前项目用：

```bash
npm install --registry=https://registry.npmmirror.com
```
:::

## 跑完之后

环境配好了，Node 能跑，依赖装完，后端起来了。
