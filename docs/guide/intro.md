# 写在开头

这份教程最后会给你一个能跑的任务清单应用：加任务、勾完成、删任务，数据存在本地，重启不丢。

但真正想教你的不是这个应用怎么写，是**每一行代码为什么放在那个位置**。前端的输入校验和后端的校验为什么必须是同一份、乐观更新失败时界面该回到什么状态、请求发不出去和请求返回 500 在界面上该怎么区分——这些是「会写」和「写得住」之间的差别。

## 你属于哪种情况

| 你的情况 | 建议从哪读起 |
| --- | --- |
| 写过 HTML/CSS，没写过 JavaScript 逻辑 | 先跑 [第1章](/guide/ch01)，把两个终端开起来 |
| 写过 React 或 Vue，从没碰过后端 | 直接进 [第2章](/guide/ch02)，那里开始处理数据存哪、谁来校验 |
| 后端熟，前端只会点 | [第1章](/guide/ch01) 的代理配置和 [第3章](/guide/ch03) 的状态处理是重点 |
| 只是想搞懂「为什么前后端要分开」 | [第1章](/guide/ch01) 的「一次请求穿过了什么」一节，然后读 [第3章](/guide/ch03) |
| 只想看代码 | [代码仓库](https://github.com/RIP-LIP/fullstack-todo-app)，每章一个 tag |

## 不覆盖什么

先说清楚，免得你读到一半发现要找的东西不在里面：

- **不教算法和数据结构**。这里没有一个排序算法。
- **不教 CSS 审美**。样式能看就行，界面丑不丑不在讨论范围。
- **不教部署后端**。第 6 章才讲，而且只到「能跑起来」为止。
- **TypeScript 只讲用到的地方**。不会给你讲泛型的协变逆变。遇到看不懂的类型写法，标记出来往后看，或者直接用 `any` 跑通再回来。
- **不讲算法课和八股**。面试题不在这里。

## 读之前要准备什么

| 需要 | 版本 | 怎么确认 |
| --- | --- | --- |
| Node.js | 22 或更高 | `node -v` |
| npm | 10 或更高 | `npm -v` |
| 一个终端 | 任意 | — |
| 浏览器 | Chrome / Edge / Firefox | — |

SQLite 不用装。数据库文件由程序自己创建，这是选它当第一个数据库的主要原因——你不用先花一个小时把环境配通，才能看见第一行数据。

## 两个仓库

| 仓库 | 是什么 |
| --- | --- |
| 你正在读的这份 | 教程正文 |
| [fullstack-todo-app](https://github.com/RIP-LIP/fullstack-todo-app) | 教程里所有代码的真实位置，可运行 |

## 每章的固定结构

```
目标 → 手写一遍 → 验证 → 常见误区 → 隐性规则 → 跑完之后
```

其中两个是刻意设计的：

**验证**一节给的是「你应该看到什么」，不是「应该成功」。如果你看到的和这里写的不一样，以你看到的为准，README 的常见问题里有排查顺序。

**常见误区**配的是可执行的解法，不是「注意一下就好」。踩过的坑如果只给一句提醒，下次换个项目你还会踩。

## 从哪里开始

打开终端，clone 应用仓库：

```bash
git clone https://github.com/RIP-LIP/fullstack-todo-app.git
cd fullstack-todo-app
```

然后进 [第1章 跑起来，看懂一次请求](/guide/ch01)。
