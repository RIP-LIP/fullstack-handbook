# 写在开头

主线项目是**任务清单**：加一条、勾完成、删一条。四个功能，两小时能写完。

教程花时间的不在这四个功能，在**每一步怎么确认真的成了**，以及**不成的时候按什么顺序查**。

## 章节顺序

| 页面 | 内容 | 从这里进的情况 |
| --- | --- | --- |
| [环境配置](/guide/setup) | 装 Node、认识终端、装依赖 | 没配过环境 |
| [基础概念](/guide/basics) | 端口、状态码、JSON、代码跑在哪 | 搞不懂前后端为什么分开 |
| [项目启动](/guide/ch01) | 两个服务同时起，一次请求穿过代理 | 环境好了，直接想跑 |
| [数据存储](/guide/ch02) | SQLite、四个接口、共享校验 | 写过前端，没碰过后端 |
| [前端交互](/guide/ch03) | 四种状态、乐观更新、竞态 | 上一章跑通了 |

每章的结构固定：

```
目标 → 手写一遍 → 验证 → 常见误区 → 隐性规则 → 跑完之后
```

**「验证」给的是「你应该看到什么」**，不是「应该成功」。如果你看到的和这里不一样，以你看到的为准。

**「常见误区」配的是能直接执行的解法**，不是「注意一下就好」。

## 代码在哪

| 仓库 | 内容 |
| --- | --- |
| [fullstack-todo-app](https://github.com/RIP-LIP/fullstack-todo-app) | 所有代码，可运行 |

**所有命令都在应用仓库的根目录执行**，不是在教程仓库。教程仓库只有文档。

每章一个 git tag，可以回到任意一章的起点：

```bash
git checkout v0.1
```

## 一条路线走下来

```bash
git clone https://github.com/RIP-LIP/fullstack-todo-app.git
cd fullstack-todo-app
npm install
```

然后按顺序读 [环境配置](/guide/setup)。
