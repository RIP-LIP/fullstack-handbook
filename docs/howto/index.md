# 场景索引

按「你遇到什么麻烦」查，不按工具查。每一项都指向具体页面里的小节，不是目录。

## 先判断：这是 bug 还是不是 bug

动手之前先分一下类，方法见 [排障四阶段](/toolkit/quality#排障四阶段)：

| 症状 | 大概率是 | 去哪 |
| --- | --- | --- |
| Network 面板里**根本没有**这条请求 | 请求没发出去（后端没起 / 代理没配） | [项目启动](/guide/ch01#_8-两个隐性规则) |
| 有一条红色请求，状态 4xx | 路径或参数不对 | [项目启动](/guide/ch01#_9-常见误区) |
| 有一条红色请求，状态 5xx | 服务端自己出错 | 看后端终端输出 |
| 什么都没有，状态栏显示 CORS | 跨域 | [项目启动 › 如果不做代理会怎样](/guide/ch01#_7-如果不做代理会怎样) |

::: tip 修到第三次还不好，就别修了
[排障四阶段](/toolkit/quality#排障四阶段) 的硬规定：**少于 3 次回到第 1 阶段重新分析；≥ 3 次停下质疑架构**，和人讨论，不要试第四次。

**三次都失败说明你对问题的理解有结构性错误**，继续试只是在加深错误。
:::

## 查不到的时候

按这个顺序走，别跳：

1. 先按上面的四类分一下，**确定是「请求没发出去」还是「发出去了但失败」**——这两类在浏览器里长得不一样
2. 用 `curl` **直连后端**（绕过代理）试一次。通了说明后端和路由都没问题，问题在前端或代理
3. 翻对应章节的「常见误区」——排查步骤按顺序给的，别跳着试
4. 还没定的话，按 [排障四阶段](/toolkit/quality#排障四阶段) 走，不要凭印象猜

::: tip 排查前先把终端留在那儿
后端终端要开着看输出。关掉它等于杀掉后端，浏览器只给你一句信息量很低的 `Failed to fetch`。
:::
